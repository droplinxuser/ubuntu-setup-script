Two edits the purge cannot know about were applied by hand after the script:

1. `/etc/hosts` still contained
   `127.0.0.1 wp.test.local xf.test.local chev.test.local`; the line was
   removed and the digest matches the baseline again.
2. `/etc/sysctl.conf` was non-empty (an operator block with
   `kernel.panic = 10`, `vm.nr_hugepages = 0`, `rp_filter = 2`); the
   baseline file is empty (MD5 `d41d8cd9...`), so it was truncated and
   `kernel.panic` was set back to 0 at runtime.

`tcp_bbr` remains loaded by the live SSH/qdisc state, so
`tcp_allowed_congestion_control` still lists it; the active congestion
control is `cubic` and the module reference disappears on reboot.  This is
runtime state, not a package or `/etc` difference.
