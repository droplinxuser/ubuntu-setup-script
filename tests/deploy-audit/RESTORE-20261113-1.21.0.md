metal.  A manifest (`host-manifest.sh`: packages, `/etc` digests, unit files,
sysctl, users, sockets, firewall, swap) was taken before the first install
and compared with `compare-manifest.sh` after `restore-baseline.sh`.

## Restore

`restore-baseline.sh BASELINE setup.sh` ran `setup.sh --purge all` (puts the
recorded sysctl, limits, governor, hostname and timezone back), purged every
package that was not in the baseline, removed the APT sources and keys, the
service trees, data, caches, state, helper scripts and accounts, reset and
disabled ufw, dropped its empty chains and unloaded the kernel modules the
profile had loaded.

Final comparison against the baseline:

| Item | Result |
|---|---|
| Packages | 526 = 526; none added, removed or changed in version |
| `/etc` file digests | 0 added, 0 removed, 0 changed |
| Enabled unit files | identical |
| Users and groups | identical |
| Listening sockets | identical (22, local resolver) |
| Firewall | ufw inactive, as before; no chains loaded |
| Root crontab | none, as before |
| `/var/www`, `/etc/angie`, `/etc/php`, `/var/lib/setup.sh`, cache directories | gone |
| `/root` | the same entries as before the run |
| `/tmp` | only the systemd private directories and the X11 socket directories |
| Kernel modules `tcp_bbr`, `sch_fq`, `nf_conntrack`, `xt_*` | unloaded |
| Failed units | 0 |

What still differs from the baseline, none of it persistent:

- `net.ipv4.neigh.{default,enp2s0}.unres_qlen_bytes` is 211090 instead of
  212992.  The kernel derives it when an interface is set up; a reboot
  resets it.  The host was not rebooted.
- `packagekit.service` and `polkit.service` were running (started by the
  apt activity; both exit when idle) and `anacron.service`, a oneshot, was
  not running at that moment.
- `/var/log/dpkg.log`, `/var/log/apt/history.log` and the journal record the
  run, and the APT package lists were refreshed (root filesystem use: 2.0 GB
  against 2.3 GB at the start, after `apt-get clean`).
