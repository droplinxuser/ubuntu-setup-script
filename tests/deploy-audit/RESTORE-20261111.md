# Restore report - 2026-11-11 (setup.sh 1.19.2 audit)

Target: `rt@192.0.2.10` (`audit-host`, 16 threads / 27 812 MiB / NVMe,
Ubuntu 26.04.1).  Baseline captured before any change: 526 packages (the full
host manifest is kept off the public repository; it carries machine
identifiers).

## Sequence

1. `setup.sh --purge all` - stops every managed service, restores the
   recorded sysctl, UFW and hostname settings, and moves generated files to
   `/tmp` without deleting anything.
2. `restore-baseline.sh` with the package delta from
   `tests/deploy-audit/delta-20261111.md` - `apt-get purge` of the 82 packages
   the run added, `autoremove --purge`, removal of the Angie/Elastic/Sury/
   NodeSource repositories and keyrings, service trees and data
   (`/etc/angie`, `/etc/php`, `/etc/mysql`, `/etc/valkey`,
   `/etc/elasticsearch`, `/var/www`, `/var/lib/setup.sh`, `/var/lib/mysql`,
   `/var/lib/valkey`, `/var/lib/elasticsearch`, `/var/cache/php`,
   `/opt/stress-node`, `/var/lib/stress-site`), the generated systemd units
   and sysctl/modules files, and the `elasticsearch`/`valkey`/`redis`
   accounts.
3. Residual sweep: MariaDB backup config, the per-service systemd
   `*.service.d` drop-ins, the test vhosts left in `/etc/hosts`, the loaded
   `tcp_bbr` module, the checkout under `/home/rt/work` and the run logs.
4. `host-manifest.sh` compared against the baseline.

Remaining differences from the pre-test image, all expected and non-active:

- **4 stale UFW rule backups removed** (`/etc/ufw/*.rules.20261110_222357`).
  They were already present in the baseline image (left by an earlier UFW
  run) and `restore-baseline.sh` removes `*.rules.YYYYMMDD` backups by design.
- **Account database backups rewritten** (`/etc/passwd-`, `/etc/shadow-`,
  `/etc/group-`, `/etc/gshadow-`).  Package installation and removal update
  these historical "previous version" copies; the live `passwd`, `shadow`,
  `group` and `gshadow` digests are byte-identical to the baseline.
- Runtime-only counters (`net.ipv4.neigh.*.unres_qlen_bytes`) differ until the
  next boot; they are derived from memory at boot, not configured by setup.sh.

No package, service, port or managed configuration file from the test remains.
