Target: `rt@192.0.2.10` (`audit-host`, AMD Ryzen 7 8745HS, 16 threads,
27 812 MiB, NVMe, Ubuntu 26.04.1, bare metal).

The full host manifests are not published: they carry machine identifiers
(Machine ID, product UUID, hardware serial and `/etc` digests).  The counts in
this document are the evidence; local copies stay with the operator.

## What the run added

- **83 packages** (Angie + Brotli module, PHP 8.5 and extensions, MariaDB,
  Valkey, Elasticsearch, Node.js, nvme-cli/smartmontools/sysstat/gifsicle,
  and their library dependencies). Full list below.
- **258 files under `/etc`** (115 Angie, 41 PHP, 13 Elasticsearch, 12 MariaDB,
  systemd drop-ins, third-party APT sources/keys, fonts/logcheck/sysstat
  conffiles pulled by the packages).
- `/var/www` (WordPress 7.1.4, XenForo 2.3.13, synthetic stress site),
  `/var/lib/setup.sh`, service data directories, `/swapfile`,
  `/opt/audit-tools`, `/opt/stress-node`, cache trees under `/home`,
  the managed root crontab, UFW rules and the performance governor.

## Cleanup sequence

1. `setup.sh --purge` (all): stopped and disabled the five services, removed
   the managed cron block, restored the recorded sysctl/PAM/DNS/hosts/
   hostname/timezone/UFW/governor state, and left the configuration tree in
   place (the script never deletes).
2. `apt-get purge` of the 83 packages, then `apt-get autoremove --purge`,
   `apt-get clean` -> **526 packages**.
3. Removed the service trees (`/etc/{angie,php,mysql,valkey,elasticsearch}`,
   `/var/www`, `/var/lib/{setup.sh,mariadb,elasticsearch,valkey,redis}`,
   caches, `/opt/*`), third-party APT sources/keys, systemd drop-ins,
   `/swapfile` + fstab entry, and the package users/groups.
4. Removed the audit tooling and scratch data (`/home/rt/{src,work}`,
   `/opt/audit-tools`, `/tmp` run files) and the temporary SSH key added for
   this session.

`dpkg --verify` reports only the provider image's pre-existing missing X11
files (`/etc/X11`, two Xsession conffiles) and `/etc/apparmor.d/disable`,
none of which this audit touched. No service, config tree, cron entry or
firewall rule from the test remains.

One note: the nominal baseline was not fully clean. `/var/lib/mariadb`
survived a previous session's package purge and still held orphaned
`xenforo`, `wordpress` and `stress_test` databases (224 XenForo tables,
created at 15:17 local before this audit). They were dropped during the
WordPress/XenForo deployment and the data directory was removed with the
restore, so the host is now consistent with the 526-package image.
