| Chevereto login | One clean retry on a 403 token/session race; a second failure is fatal | 302 on the first or second attempt, never silent |
| FPM sweep tooling | `set-fpm.sh` validates with `php-fpm -t` and restores on rejection; new `dynamic N` action writes the start/spare keys a static pool lacks | dynamic-5 run keeps the site at 200; restore returns the shipped static pool |

## 4. Security checks

All vhosts answered 403 for `.env`, `.git/config`, `.htaccess`,
`wp-config.php` (+ `.bak/.save/.swp`), `composer.json/lock`, archives
(`.zip/.tar.gz/.sql/.sql.gz/.zst/.bz2`) and `.DS_Store`; 404 for
`/index.php/foo`, `/logs/`, `/mysql_database/`, `/phpinfo.php`; 400 for
`/foo/../index.php`, `/%2e%2e/...` and `/..%2f...`; 405 for
TRACE/PUT/DELETE/OPTIONS.  PHP in upload/cache directories is 403 on
WordPress and unreachable (404) elsewhere.  A forged `Host` is refused; the
guest cache key carries `$host` and only validated cookie tokens.  TLS 1.0
and 1.1 are refused; HSTS, X-Frame-Options and Referrer-Policy are present.

Operational note: `ufw limit 22/tcp` (6 connections / 30 s per source)
refuses a burst of parallel SSH/scp sessions from one workstation and keeps
extending the block while the client retries.  The audit used a single
persistent SSH master connection; automation from one admin host should do
the same (or be given an explicit `allow` rule).
