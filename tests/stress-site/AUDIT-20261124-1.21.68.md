# Audit — 1.21.68 (compiled php-fpm: package vs clang vs lean)

Date: 2026-11-24
Host: the Xeon E-2236 test host (6C/12T, 62 GB, md RAID0 NVMe, Ubuntu
26.04.1).  The host was restored to its pristine package set mid-cycle
(696 packages plus upstream drift: kernel 7.0.0-44 with its metapackages,
tzdata, python3-oauthlib), rebooted, and freshly installed for the final
comparison.  CPU mitigations were **off** for every number below (operator
request; `--basic mitigations=off`).  Pair: `server-configs-nginx` 1.6.59.
Applications: WordPress 7.1.4, XenForo 2.3.13, Chevereto 4.5.9-pro, deployed
with `deploy-three-apps.sh` (standard data set; the 20k-user forum of
1.21.67 was used for the earlier rounds in §3).

## 1. What this cycle chose and why

**Primary question (operator):** combine whatever measured best across the
web-server and PHP-runtime rounds, even at 2-10 %, for logged-in XenForo
pages that are not cached; compiling from source or switching servers is
acceptable.

* **Web server:** Angie stays (1.21.60 and 1.21.67: OpenLiteSpeed ties on
  members and loses 16-23 % on cached pages; Caddy/nginx forks gave nothing
  over Angie).
* **Runtimes:** FrankenPHP worker mode, RoadRunner, Swoole/OpenSwoole,
  Workerman, ReactPHP and AMPHP need the application ported to a resident
  worker model (1.21.61); XenForo, WordPress and Chevereto are not, so
  PHP-FPM stays.
* **Compiler:** the earlier verdict (1.21.64-66: no gain) was biased.  Those
  harness builds turned GCC's global registers off and never tried BOLT.
  This cycle re-measured with both fixed (§3), and BOLT made the
  difference.

**Audit:** nine findings ranked by impact, all fixed with a regression test
each (§5).  The operator then asked for three php-fpm builds side by side,
a lean module set, latest upstream sources with a versions file, GD instead
of imagick, and php-fpm loading only what the three applications need; all
of that shipped and is measured in §4.

## 2. Method

PHP 8.5.13, the same managed `php.ini` (OPcache 512 MB, tracing JIT 64 MB,
`opcache.jit=tracing`, hot loop/func/return/side-exit 64/127/16/64), 12
static PHP-FPM workers, HTTP/1.1 over TLS from loopback `wrk`
(`bench-php-sources.sh`: 100 connections, 12 s per tier, 5 rounds with the
arm order rotated each round, clock pinned at 3.6 GHz with
`set-clock.sh`).  Medians with the min-max spread; under ~3 % inside the
spread is noise.  unattended-upgrades and needrestart were stopped during
measurement: in the first matrix they restarted php-fpm mid-tier (kernel
7.0.0-44 install), and that row (674 req/s, 6,682 non-2xx) is excluded.

## 3. Compiler rounds (20k-user forum, XenForo member thread / home)

| Arm (vs Sury 210 / 231 req/s) | Thread | Home |
|---|---:|---:|
| clang -O3 -march=native | +2.9 % | +2.6 % |
| clang ThinLTO | +6.7 % | +6.5 % |
| clang PGO | +3.8 % | +4.3 % |
| clang PGO + BOLT | +9.0 % | +9.1 % |
| GCC (HYBRID VM, global registers) | +1.9 % | +2.2 % |
| GCC PGO (no LTO: GCC LTO and global registers do not link) | +1.9 % | +2.2 % |
| clang ThinLTO + BOLT (confirm round) | +11.0 % | +13.2 % |
| drop-in: Sury's core + Sury's extensions, ThinLTO | +5.7 % | +4.7 % |
| drop-in + BOLT (LLVM 21) | +10.0 % | +9.5 % |
| lean upstream + BOLT (LLVM 23, XenForo-only module set) | +7.9 % | +9.3 % |

Cached tiers stayed within ±1 % in every round.  PHP 8.5 built with clang
19 or later uses the TAILCALL VM; GCC uses the HYBRID VM with global
registers.  BOLT gains come from code layout (ext-tsp block order, cdsort
function order, hot/cold splitting) driven by perf LBR samples of live
workers.  The lean upstream build (newest OpenSSL 4.1, ICU 79, curl 8.23,
PCRE2 10.49, ThinLTO across PCRE2/zlib/libxml2) tied the drop-in on
XenForo (−2.2 % / −0.8 %, inside the spread): with the tracing JIT, page
time is in the VM and JIT code, not in the libraries.

## 4. Final comparison: three builds, three applications

Fresh install, `SETUP_PHP_BUILD=clang` and `=lean` built and BOLTed through
`setup.sh --optimize` under mixed load (XenForo members, WordPress members,
Chevereto uncached guests), binaries copied to bench arms, then
`SETUP_PHP_BUILD=package --optimize` back to Sury.

| Tier | package | clang | lean |
|---|---:|---:|---:|
| XF member thread | 224 (205-225) | 237 (219-237) +5.8 % | 234 (213-234) +4.5 % |
| XF member home | 418 (384-421) | 443 (405-444) +6.0 % | 439 (415-441) +5.0 % |
| WP member home | 139 (138-139) | 132 (131-144) −5.0 % | 142 (141-142) +2.2 % |
| WP member post | 128 (127-129) | 122 (121-134) −4.7 % | 131 (130-132) +2.3 % |
| Chevereto guest home, uncached | 1,228 (1,165-1,398) | 1,328 +8.1 % | 1,339 +9.0 % |
| Chevereto member explore | 440 (427-530) | 483 (376-592) +9.8 % | 448 (423-545) +1.8 % |
| XF guest home, cached | 116.4k | 111.9k −3.9 % (inside spread) | 116.5k 0.0 % |

p99 followed the medians: XF member thread 619 / 562 / 584 ms.  One BOLT
profile now serves three applications, so XenForo's gain is smaller than
with the XenForo-only profile of §3 (+6 % instead of +10 %).  The clang
WordPress rows are bimodal (131-144); the lean rows are tight.

**Verdict (§0):** both compiled builds are faster than Sury for XenForo
members (+4.5-6 %) and Chevereto (+8-9 %); `lean` is the only one ahead on
WordPress.  The default stays the package (no toolchain, Sury's security
updates); `clang` and `lean` are opt-in and kept side by side for later
re-measurement.

**Modules loaded by php-fpm** (all three builds): Core ctype curl date dom
exif fileinfo filter gd gmp hash iconv igbinary json lexbor libxml mbstring
mysqli mysqlnd openssl pcre PDO pdo_mysql random redis Reflection session
SimpleXML sodium SPL standard uri xml xmlreader xmlwriter zip zlib, OPcache;
`lean` adds intl (the package install does not include php-intl).  Disabled
for php-fpm on the package/clang builds: calendar ffi ftp gettext phar posix
readline shmop sockets sysvmsg sysvsem sysvshm tokenizer xsl.  Chevereto
runs on GD; imagick is not installed.

**Final PHP parameters (unchanged):** 12 static workers, OPcache 512 MB,
tracing JIT 64 MB, 64/127/16/64.  **Maximum PHP per application:** 8.5 for
WordPress 7.1.4, XenForo 2.3.13 and Chevereto 4.5.9 (all suites pass on all
three builds); 8.6 was not re-tested this cycle.

## 5. Fixes (each with a regression test in `tests/test-tuning.sh`)

1. `--upgrade-php` replaced an operator-edited `www.conf` with the template;
   it now migrates the old pool and falls back to the template only when
   `php-fpm -t` rejects the result.
2. `php_upgrade_optimize` ran under `cmd || rc=1`, which suspends `set -e`
   inside it; it now records its status and is called plainly.
3. `--mariadb` on a host with PHP left the pool sized for no database
   without saying so; it now warns.
4. Four MariaDB keys forced a restart although they apply at the next one.
5. Valkey `g`/`m` units were read as binary.
6. `OMP_NUM_THREADS`/`OMP_THREAD_LIMIT` shrank `nproc` and the sizing.
7. (1.6.59) Encoded XenForo style/language/variation cookies could split
   the guest cache key; they now bypass it.
8. (1.6.59) PHP under plugin/theme `vendor/` or `node_modules/` was
   executable; WooCommerce/EDD private uploads were public.
9. (1.6.59) Upstream `X-Forwarded-For` passed client-supplied chains from
   untrusted peers.

Also found while measuring: the lean build's EXIT trap named a local
(`set -u` failed after a successful build); GMP's assembly stopped BOLT
(88 code-offset relocations in data; GMP is now built in C); PECL igbinary
3.2.16 needs the `php_smart_string.h` wrapper PHP 8.5 removed; the restore
script purged the kernel metapackages with the kernel unattended-upgrades
added; `switch-php-arm.sh` needed a CLI the lean arm does not have.
