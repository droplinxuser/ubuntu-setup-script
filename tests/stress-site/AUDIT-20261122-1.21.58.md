# Audit — 1.21.58 cycle (Ubuntu 26.04.1, Angie, PHP 8.5)

Date: 2026-11-22
Host: dedicated Xeon E-2236 test host (Coffee Lake, 6C/12T), 62 GB, md RAID0
over two NVMe drives, Ubuntu 26.04.1, kernel 7.0.0-43, stock kernel command
line (CPU mitigations on: PTI, IBRS).  Pair: `server-configs-nginx` 1.6.51.
Applications: WordPress 7.1.4, XenForo 2.3.13 (Hampel Seeder 1.0.0b11:
20,060 users, 10,200 threads, about 27,000 posts; SV RedisCache /
FloodCheck / ViewCounter / StandardLib), Chevereto 4.5.9-pro.
Load: loopback HTTPS with `wrk -t4 -c100`, 10 s after a 2 s warm-up, three
runs per row, median shown.  Angie and PHP-FPM CPU per request are the
`usage_usec` deltas of their systemd cgroups divided by the requests wrk
completed (`compression-bench.sh`).

Primary focus: gzip vs Brotli vs zstd for live production use (guest,
member and static tiers), and ship the winner as the default.

## 0. Method notes

- **Interleave, never block.**  The first baseline ran each encoding's three
  runs back to back.  The first encoding of every page came out up to 24 % faster
  than the rest (WordPress cached post: 90.8k vs 73.3k for the same stored
  gzip body, first block-ordered run, discarded); re-running the three
  headers round-robin gave 73-77k for all of them.  The CPU's boost budget favours whatever runs first, so every
  comparison below rotates encodings (or configurations) within each round
  (`compression-bench.sh` pass 2, `comp-ab` rotation).  Rotation reduces the
  effect but does not remove it: the first slot of each round still ran up
  to 16 % faster on the cached tier (WordPress browser row 84,952 vs
  73,135).  The old default was placed first in the A/B rotations, so the
  measured gains are conservative.
- **One run was invalid and is not used:** a zstd level sweep in which the
  helper wrote the zstd module stanza twice; `angie -t` failed, nothing
  reloaded, and every "level" was level 6.  Detected because all five rows
  were identical; re-run after the fix.
- **Content drift.**  Between the baseline and the final matrix the suites
  and seeding added content (XenForo thread 78.8 -> 89.1 KB uncompressed,
  Chevereto explore 61.3 -> 76.4 KB), so absolute guest/member rows of the
  two matrices are not comparable; the controlled A/B tables are.  Static
  files are byte-identical in both, so the static rows compare directly.
- Cloudflare asks origins for `br, gzip` only (zstd is a visitor-side
  option at its edge), so the `br, gzip` rows are what a Cloudflare-fronted
  origin serves; `gzip, deflate, br, zstd` is a current Chrome/Firefox/Edge
  browser hitting the origin directly.

### 2.6 Filter order

With both modules loaded, the output filter loaded **last runs first**.  The
1.21.57-era stanza name `40-zstd.conf` sorts before `50-brotli.conf`, so
Brotli answered every client, including `zstd`-first ones.  As `60-zstd.conf`:

| Accept-Encoding | sent |
|---|---|
| `gzip, deflate, br, zstd` | zstd |
| `br, gzip` (Cloudflare) | br |
| `gzip, deflate, br` (Safari) | br |
| `zstd;q=0, br` | br |
| `br;q=1, zstd;q=0.1` | zstd (q-order between two accepted codings is not ranked; harmless) |

## 3. Verdict

- **Static:** precompressed `.br`/`.gz` siblings, on by default: 22-30x
  throughput in the rotated A/B (16-28x in the before/after matrix), 13-18 %
  fewer bytes for Brotli clients (4-10 % for gzip-only clients), 1/18 to
  1/34 of the Angie CPU.
- **Dynamic (members, uncached pages):** zstd 3 for clients that offer it,
  Brotli 4 for the rest (Cloudflare, Safari), gzip 4 last.  For a
  Cloudflare-fronted origin nothing changes on this tier (it never asks for
  zstd); direct browser traffic gets Brotli-class bytes for 40 % of the
  Angie CPU.
- **Guest cache:** keep the stored gzip body (any compressing client gets it
  at 0.06-0.11 ms); WordPress/Chevereto store level 6 instead of 4.

## 5. Security and correctness (audit workflow)

A read-only audit of both repositories ran six finder agents (security,
compression/cache, parity, auto-tuning, CLI, robustness); each finding was
then checked by two independent skeptics told to refute it.  24 raw
findings: 21 upheld by both, 2 split, 1 rejected.  Fixes were made in
disjoint file groups and each diff was reviewed adversarially again.

| Finding | Evidence | Fix / regression test |
|---|---|---|
| Member page stored for guests via `xf.session=<sid>` (PHP folds `.`, space, `[` to `_`) | reproduced: MISS then HIT with the logged-in page, served to the next cookie-less guest | maps accept folded separators, any prefix, `%` in a name bypasses; after the fix BYPASS, guest MISS with a guest page; `guest-cache-cookie-test.sh` +5 probes, unit tests |
| `--optimize` stripped `$req_encoded_path` / `$cache_uri_tracking` from XenForo's bypass lines | source + unit test asserted the stripped line | only legacy `$cookie_xf_*` lines rewritten; host: lines intact after `--optimize`, tracking URL never stored (MISS x3), `%77hats-new` BYPASS; `security-probe.sh` +2, unit tests |
| setup-managed XenForo map: `gzip;q=0` treated as gzip | source | strict rule; unit tests |
| Basic-auth password files reset to 0644 by the tree normaliser | source | `root:<worker group> 0640` before the normaliser, skipped by it; unit |
| Precompressed siblings stale after a shrink below 1 KiB, a rollback, or an upgrade mid-pass; left behind when the feature is turned off | source | rebuilt on any mtime difference, size/mtime checked around compression, removed on shrink, `--remove` sweep; unit tests |
| `--upgrade-php` drops other versions' pools/inis; same-version run purges everything; rollback deletes package files; dry run names a different source | source | refuse + override, extension-only path, tracked rollback, shared source pick; unit |
| Live pool on TCP gets `local_php` pointed at the socket after the sync (502) | source | upstream follows the live listen; unit |
| Session hardening, mitigations pin, planner parity (pending reset, explicit children, max_connections cap, cache vs free disk, non-root dry run, install budget), PHP refresh rollback | source | see CHANGELOG 1.21.58; unit |

The split finding on `--purge basic` (mitigations pin) was confirmed in
code and fixed; the other split finding (PHP refresh rollback) was fixed
defensively.
