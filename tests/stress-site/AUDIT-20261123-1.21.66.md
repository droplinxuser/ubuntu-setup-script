# Audit — 1.21.66 (PHP build sources, last round; security and robustness fixes)

Date: 2026-11-23
Host: the Xeon E-2236 test host (6C/12T, 62 GB, md RAID0 NVMe,
Ubuntu 26.04.1, kernel 7.0.0-43), checked against its pristine state before
the install (696 packages, clean `/root` and `/home/ubuntu`, no stack
directories) and restored afterwards.  CPU mitigations were **off** for every
number below (operator request; `--basic mitigations=off`, a test-host-only
GRUB drop-in removed at restore).  Pair: `server-configs-nginx` 1.6.57.
Applications: WordPress 7.1.4, XenForo 2.3.13 (200 threads / 2,600 posts /
60 users), Chevereto 4.5.9-pro, deployed with `deploy-three-apps.sh`.

## 1. What this cycle chose and why

The primary question (PHP install source and CentminMod build flags) was
answered in 1.21.64 (Sury, Ubuntu, source `-O2`, source `-O3
-march=native`: no gain) and 1.21.65 (LTO neutral, PGO 5-10 % slower).
Those measurements were not repeated.  This round measured only the levers
still open:

1. CentminMod's `GCC_FALIGN_FUNCTION=y` on its own, without LTO.
2. CentminMod's `CLANG_PHP=y`: the same flags with clang.
3. **Every module from source**, igbinary included.  1.21.65 could not
   build igbinary 3.2.16 against 8.5; 3.2.17RC1 compiles, so the
   "downgrade to 8.4 if needed" fallback was not needed.  PHP 8.4.28 was
   measured anyway, as its own arm, because 8.4 against 8.5 had never been
   measured here.

A four-reviewer audit of both repositories (parity, tuning, Angie security,
robustness), with an adversarial check on each finding, produced 16
findings.  7 were refuted and 9 confirmed; all 9 are fixed below.  The
host work found one more bug, a post-rollback 502 (§5.3).

### 2.1 Harness defect found and fixed: no zlib in the source builds

The first matrix gave a cached guest tier of 6k req/s instead of 98k
whenever a source arm was serving.  Cause: `build-php-source.sh` and
`build-php-max.sh` never passed `--with-zlib`.  The managed ini turns on
`zlib.output_compression` for WordPress and Chevereto roots, so the guest
cache stores PHP's gzip body.  Without zlib, PHP sent identity, the
encoding guard refused to store the page, and every "cached" hit went to
PHP.  On the uncached tiers the same gap meant less PHP work (Angie
compressed instead).

That bias favoured the source builds on WordPress and Chevereto tiers in
1.21.64/65 as well.  Their verdicts ("no gain") therefore stand, and the
XenForo tiers were not affected: XenForo gets an empty `Accept-Encoding`
from Angie.

All builds now pass `--with-zlib --with-sodium` (sodium: WordPress falls
back to a PHP polyfill without it).  Parity was checked before the final
matrix.  Under `src-clang` a guest page is `[gzip] MISS` then `[gzip] HIT`,
the same as Sury.  The matrices that count are the post-fix ones; the
pre-fix matrix is listed only as a cross-check of the XenForo rows.

## 3. Method

* Clock pinned at 3.6 GHz (`set-clock.sh 3600`; the host's turbo is
  power-limited).
* `bench-php-sources.sh`: 3 rounds, arms rotated forward then backward,
  the guest cache emptied before each arm, each URL warmed for 2 s, c=100,
  10 s, loopback `wrk`.
* Median of 3 with min-max spread.  A change inside the spread or under
  ~3 % is noise.

### 4.4 Verdict

* **clang** is the only build with a repeatable edge: +3 % on XenForo
  member pages, outside the spread in two of three matrices.  It is flat
  on WordPress and Chevereto and within 1 % of Sury on the CLI probe.  It
  sits right at the 3 % bar, on one application.  It is not shipped: a
  compiled PHP needs a toolchain and a manual rebuild for every security
  release on every host, and that costs more than 3 % on one tier buys.
* **GCC `-O3 -march=native`** with or without CentminMod's
  `-falign-functions=32` is 1-5 % slower than the distribution's `-O2`.
  This agrees with 1.21.64.  falign is not the cause (gccnoal is no
  better).
* **PHP 8.4 is slower than 8.5** on every tier (−2.9 % to −4.3 %), and
  its object/method section is 21 % slower.  With igbinary now building on
  8.5 there is no reason to downgrade.
* **Sury stays.**  The harness keeps every arm (`build-php-max.sh` now
  takes `CC=clang`, `NO_FALIGN=1`, `PHP_INI_DIR` and `IGBINARY_VER`), so
  the clang result can be re-checked when compilers or PHP move.

### 5.2 Robustness and tuning (ubuntu-setup-script)

| Finding | Evidence | Fix |
|---|---|---|
| Interrupted `--upgrade-php` left no PHP | `lib/restart.sh` `on_exit` had no rollback; `run_php_upgrade` rolled back only on explicit failure branches | `PHP_UPGRADE_IN_FLIGHT` around purge to serving; `on_exit` rolls back while it is set; HUP ignored in that window |
| Auto swap released the live file first | `configure_swap_auto` called `release_swap_file`, counted the old file as free; `create_swap_file` builds beside it and could `die` with swap off | pure `swap_auto_new_size` counts real free space only; the swap itself is left to `create_swap_file`; `release_swap_file` removed |
| MariaDB install left stopped after a restart failure | `install_mariadb` restored its backup only on a parse failure | restore the copy and restart on a start failure too; wait 300 s (as `mariadb_restart_probe`) before the grants |
| Valkey install pinged 127.0.0.1:6379 | adopt keeps an operator bind/port | `valkey_pong` takes endpoint args; the install pings the socket it wrote |
| Two running FPM versions each got the full pool | `php_pool_max_children` returned the max; plan/MariaDB/Valkey counted one pool | pool total = sum over running versions; each version gets `php_split_children` of the plan (stable across runs); single-version hosts unchanged |
| Angie worker table and listen backlog had no value tests | `angie_worker_limits`, `effective_backlog` unreferenced in tests | value checks for 1-512 CPUs, dedicated and VPS, and the headroom invariant |

Refuted in the adversarial pass (not changed): FPM `[global]` template on
`--optimize`, `cloudflare.sh` on `--optimize`, the Cloudflare migration on
a repeat `--angie`, the `/usr/bin/php` pin and session GC timer in
`--optimize`, an upper clamp on `SETUP_PHP_WORKERS_PER_CPU`,
`fs.inotify.max_user_watches` on small hosts, and the inline sysctl
values.  Each was either intended and documented or not a defect.

### 5.3 Found on the host: a rollback that "succeeded" into 502

The interruption test (SIGTERM to `--upgrade-php=8.6` just after "PHP 8.6
installed") rolled back as designed, and `php8.5-fpm` was active.  Every
site still answered **502**.  The reinstalled package's postinst had
started FPM on the stock tree (`/run/php/php8.5-fpm.sock`).
`php_upgrade_rollback` then restored the managed tree but called `systemctl
enable --now`, which leaves a running unit alone, so the shared
`/run/php/php-fpm.sock` never came up.  This is a pre-existing bug: every
rollback path (failed purge, failed install, inactive target) shared it.
The rollback now restarts FPM and checks that the restored pool's socket
listens.

Re-run of the same interruption: `rc=143`, "PHP 8.5 is active again (pool
on /run/php/php-fpm.sock)", WordPress 200 at t+0, t+3 and t+10 s.

## 9. Restore

The audit trees outside the package delta were removed first (the
`php-src-*.service` units, `/opt/php-{falign,clang,gccnoal,cm84}`,
`/etc/php-src`, their logs).  Then `restore-baseline.sh` ran from `/tmp`
with `--purge all`.  `/root/audit`, `/root/work`, `/root/.debug` and the
upload directory were deleted and the host rebooted.  A fresh
`host-manifest.sh` against the pre-install baseline:

* **696 -> 696 packages**, none added, removed or version-changed.
* **0 `/etc` files added, removed or changed.**  One manual step:
  `/etc/hosts` came back with one extra trailing newline, and removing that
  byte restored the baseline digest exactly.  1.21.64 hit the same
  one-byte drift; its source is not yet found (open item).
* Enabled units identical.  Active services: only `systemd-timedated`,
  which the manifest's own `timedatectl` call starts on demand.
* sysctl: only `kernel.random.boot_id`, `net.core.netdev_rss_key` and
  `net.ipv4.tcp_fastopen_key`, which change every boot.
* Mitigations back on (`Mitigation: PTI`, no `mitigations=off` on the
  command line).  No `/swapfile`, no `/var/www`, `/etc/angie` or
  `/etc/php`; `/root` and `/home/ubuntu` hold only their baseline entries.
