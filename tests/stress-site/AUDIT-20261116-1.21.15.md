## 1. Findings and fixes

### 1.1 server-configs-nginx 1.6.32

| Area | Finding | Fix | Verification |
|---|---|---|---|
| Login limiter | `$req_login_key` matched `$request_uri` while Angie routes on the decoded `$uri`; `POST /%77p-login.php` reached wp-login.php unthrottled (30 r/s instead of 20/min). | Key is `"$request_method:$uri$is_args$args"`. | 14/14 encoded POSTs accepted before; 429 after 11 after. |
| Cache maps | Prefixes were `^`-anchored, so a subdirectory install (`/blog/wp-admin/`, `/forum/data/`) was not bypassed/denied. | Segment-boundary patterns; the maps keep `$request_uri` because `try_files` rewrites to `/index.php` (a `$uri` key lost Chevereto's home/`?lang=` no-cache tests and replayed the first session). | Guest-cookie suite 61/61; home `BYPASS`. |
| Writable PHP | The upload/data deny lived only in sample vhosts; a hand-written vhost including `h5bp/php_xf.conf` or `php_chev_cache.conf` executed PHP from `data/` and `content/`. | Deny added to the handler includes; unanchored. | `/wp-content/uploads/x.php` 403, `/blog/wp-content/uploads/x.php` 403, `/data/x.php` 404, `/forum/data/x.php` 404, `/content/x.php` 404. |
| XenForo proxy | `/proxy.php`, `/css.php`, `/webmanifest.php`, `/sitemap.php`, `/attachments` were plain prefix locations; the server-level `location ~ \.php` won, so the proxy cache and `expires` never applied. | `^~` locations. | `/css.php` 200 `text/css`, `X-Cache-Status: HIT`, 1-year expiry. |
| Upstream TLS | `proxy_ssl_verify off` in `proxy_pass.conf` / `xf_proxy_pass.conf`. | Verify on, depth 2, SNI, system trust store. | `angie -t`; no template includes them by default. |
| `$app_https` | Any client's `X-Forwarded-Proto: https` turned PHP's HTTPS flag on over plain HTTP. | Trust only the Unix peer/loopback (plus `custom.d/https_trusted_peers.map`). | Spoofed header over port 80: `HTTPS=` empty; via Anubis: `HTTPS=on`. |
| Unix backend | `$server_port` is empty on the Anubis leg, so Chevereto built `https://host:/image/...` and WordPress saw a portless canonical URL. | `SERVER_PORT $php_public_port`, `REQUEST_SCHEME $app_scheme` in `snippets/fastcgi-php.conf`; `custom.d/php_public_port.map` still wins. | PHP: `PORT=443 SCHEME=https`; Chevereto image URL `https://chev.test.local/image/...`. |
| Sample errors | Shlink/SFS samples sent every 404/5xx to `https://xx.com/xx` (`307`, replaying POST bodies) or `https://main.site/`. | Lines removed; Angie's own error pages apply. | grep clean. |

### 1.2 ubuntu-setup-script 1.21.15 (Anubis)

| Area | Finding | Fix | Verification |
|---|---|---|---|
| Backend access | `/run/angie` was 0755 and the backend socket 0777: any local account could connect with `X-Real-IP: 127.0.0.1` and skip Anubis and every IP ACL. | `d /run/angie 0750 root anubis`. | `nobody` → `000`; `anubis` → `200`. |
| Upload cap | The terminator inherited `client_max_body_size 11m` and buffered the body; uploads >11 MB got 413 before the backend limit. | `client_max_body_size 0`, `proxy_request_buffering off`. | 15 MB POST through Anubis → 200. |
| Start failure | A service that did not create its socket returned with the vhosts already moved to it; a later reload/reboot answered 502 everywhere and `anubis_managed` was false. | Restore vhosts + remove generated files + `angie -t` before returning. | Fake binary test: 3 vhosts restored, terminators removed, `angie -t` OK, site 200. |
| real-IP migration | File-global `grep` for `real_ip_header` left a CDN block's `X-Forwarded-For` in every block. | Each block drops it and gets `set_real_ip_from unix:` + `real_ip_header X-Real-IP`; other trusted ranges kept. | Unit test; live vhost has one pair per block. |
| XFF | Terminator appended `$proxy_add_x_forwarded_for`, preserving a forged left-most entry. | `$remote_addr` on HTTP and WebSocket legs. | Through Anubis with `X-Forwarded-For: 1.2.3.4`, `X-Real-IP: 5.6.7.8`: PHP sees `REMOTE=192.168.1.200`, `XFF=192.168.1.200`. |
| Purge | `--purge angie` stopped Anubis with the vhosts still on its socket; a later `systemctl start angie` answered 502. | Restore vhosts + remove Angie files, keep binary/unit/state. | Purge: 1 vhost restored, no Anubis files, `angie -t` OK; `--optimize anubis=yes` re-enables. |
| Lean policy | Assets were challenged, an empty UA was allowed, and INFO logged every proxied request. | Static-asset ALLOW, empty-UA CHALLENGE, `SLOG_LEVEL=WARN`. | `readme.html` 36 275 req/s vs 6 800 for a page. |
| Version pin | A pinned `SETUP_ANUBIS_VERSION` was compared before the override, so every run re-downloaded without restarting the service. | Compare after override; mark service dirty after install. | Unit-level review. |
| Secret/temp | The live env file was world-readable for a moment; `angie -t` used `/tmp/anubis-angie-test.$$`. | Pre-create mode 600; `tmp_file`. | Code review. |
