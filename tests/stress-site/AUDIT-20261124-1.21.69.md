# Audit — 1.21.69 (why the from-source php-fpm trailed, and one merged build)

Date: 2026-11-24
Host: the Xeon E-2236 test host (6C/12T, 62 GB, md RAID0 NVMe, Ubuntu
26.04.1, kernel 7.0.0-44), freshly installed from the restored baseline with
WordPress 7.1.4, XenForo 2.3.13 and Chevereto 4.5.9-pro
(`deploy-three-apps.sh`, standard data set).  CPU mitigations off (operator
request).  Pair: `server-configs-nginx` 1.6.59 (unchanged).

## 1. Question

1.21.68 shipped two compiled builds.  `clang` was the package's PHP version
and compiled-in core rebuilt with clang, with Sury's shared extensions.
`lean` was everything compiled from source, statically.  `clang` measured
slightly ahead on XenForo and `lean` on WordPress.  The operator asked why,
and to merge them into one source-compiled, lean build.

## 2. Method

Same as 1.21.68: PHP 8.5.13, the managed `php.ini` (OPcache 512 MB, tracing
JIT 64 MB, `opcache.huge_code_pages = On`), 12 static workers, loopback
`wrk` at 100 connections for 12 s per tier, 5 rounds with the arm order
rotated, clock pinned at 3.6 GHz.  Each build difference was isolated in its
own binary (LTO only, no BOLT), and `perf stat`/`perf record` ran under the
same XenForo member load for 20 s per arm.

## 3. Findings

**Counters (20 s under the same load):**

| Build | Instructions / page | Cycles / page | dTLB misses | Binary |
|---|---:|---:|---:|---:|
| Sury package | 91.6 M | 124.8 M | 52 M | — |
| clang + Sury extensions | 93.6 M | 125.2 M | 52 M | 21.5 MB |
| from source, ICU, PIE core | 85.5 M | 119.2 M | **233 M** | 102 MB |
| from source, ICU, all PIE | 85.5 M | 119.5 M | **232 M** | 102 MB |
| **from source, no ICU (merged)** | — | — | **53 M** | **60 MB** |

The from-source build executes about 9 % fewer instructions (no PLT calls
between core and extensions, LTO across PHP, extensions and libraries).  But
ICU, compiled in for intl, made it 102 MB and multiplied the data-TLB
misses.  In the rotated benchmark that left it 1-2 % behind the clang build.
Without ICU the misses match the package's.

**Rotated benchmark, LTO only (req/s):**

| Tier | Sury | clang + Sury ext | from source + ICU | merged |
|---|---:|---:|---:|---:|
| XF member thread | 246 | 260 | 257 | 261 |
| XF member home | 399 | 417 | 418 | 421 |
| Chevereto uncached | 1,471 | 1,504 | 1,493 | 1,520 |
| WP member home | 139 | 143 | 140 | 143 |

**Ruled out:**

* `-fPIC` against `-fPIE` for the PHP core: no measurable difference (the
  merged build uses `-fPIE`, which is correct for an executable).
* BOLT sampling with `opcache.huge_code_pages` off.  At first the profiles
  looked suspicious, because `perf` showed ~90 % of cycles as anonymous
  `[JIT]` memory, the interpreter text copied to huge pages.  But
  `perf2bolt` profiled the same number of functions either way (2,549 against
  2,541) and the binaries ran at the same speed (270 against 272 req/s).  Not
  shipped.
* intl's code paths: XenForo calls it only to romanize URLs (off by
  default) and WordPress only for non-ASCII input.

## 4. Final comparison (with BOLT, 5 rotated rounds)

| Tier | Sury | 1.21.68 clang + BOLT | merged + BOLT |
|---|---:|---:|---:|
| XF member thread | 237 (236-239) | 258 (257-259) +8.9 % | **263 (261-264) +11.0 %** |
| XF member home | 415 (413-420) | 448 (444-449) +8.0 % | **457 (446-459) +10.1 %** |
| WP member home | 139 (138-141) | 148 (145-149) +6.5 % | **150 (148-151) +7.9 %** |
| Chevereto uncached | 1,474 (1,459-1,487) | 1,539 (1,529-1,542) +4.4 % | **1,561 (1,559-1,565) +5.9 %** |

p99 is lower too (XF member thread 583 / 546 / 531 ms).

## 5. Other changes and findings

* **Second download source for everything** (see the CHANGELOG).  GMP's
  ftp.gnu.org timed out for minutes during a test build, and the old code
  failed only at `tar`.  A unit test now takes every primary host down and
  requires every component to download from its fallback.
* **Benchmark artifact, not a regression:** the first BOLT benchmark broke
  mid-run.  Chevereto's per-request session files in `/tmp` reached
  1,044,529, the tmpfs limit is 1,048,576 inodes, and MariaDB could no longer
  create temporary tables.  At 1,500 req/s the 24-minute session GC window
  holds about 2 million files; production rates stay far below that, and
  setup already turns session GC on for Chevereto.  The harness now clears
  them between arms; the rerun is the table in §4.
* Suites on the merged build through `setup.sh --optimize`: §6.

## 6. Validation

The merged build was built and BOLTed through `SETUP_PHP_BUILD=lean
./setup.sh --optimize` (the alias, persisted as `clang`) under mixed load.
Then: functional, security and cookie suites on it; a plain `--optimize`
(build current); `SETUP_PHP_BUILD=package --optimize` (build, tool, timer
and apt.llvm.org source removed).  Results: unit 1,651 checks and 227 dry runs
without a failure; build and BOLT in 8 minutes under load; security 78/78,
cookie 105/105, functional 0 failures with all three applications; the plain
`--optimize` reported the build current; the package mode left no drop-in,
tool, apt.llvm.org source or cache behind.
