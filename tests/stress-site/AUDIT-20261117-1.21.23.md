# Audit — 1.21.23 (Ubuntu 26.04.1, Angie 1.12.4, PHP 8.5)

Date: 2026-11-17
Host: `lab.local` (SER8, 192.168.1.139) — AMD Ryzen 7 8745HS, 8C/16T,
27,812 MB RAM, 903 GB NVMe, no virtualization, Ubuntu 26.04.1 (kernel
7.0.0-43), pristine baseline (505 packages) at the start of the run.

This audit re-runs the full lifecycle on a freshly reinstalled host: install,
optimize parity, three applications, all PHP versions, security probes, load
tests, package/state restore. Every number below was measured on this host,
loopback (oha 1.11.0), 10 s per tier except where noted.

## 1. Install

setup.sh --basic server=dedi host=lab.local swap=8G time=Asia/Manila \

  --mariadb user=demo pass=temp size=auto bind=127.0.0.1 \
  --valkey --elastic host=localhost ram=4g --others all

## 2. Code changes

| File | Change |
|---|---|
| `lib/services.sh` | `ensure_es_max_map_count` called an undefined `record_sysctl_originals`; every `--elastic` install printed a shell error and never recorded the boot value, so `--purge` could not restore `vm.max_map_count`. Now calls `record_sysctl_values vm.max_map_count`. |
| `lib/os.sh` | `configure_ufw` now re-runs `ufw_align_sysctl` after `ufw --force enable`. The align inside `configure_sysctl` is a no-op on a pristine host (ufw is installed later), so ufw's own `sysctl.conf` was left unaligned on a fresh install while `--optimize` aligned it. |
| `lib/validate.sh` | `generate_hostname` uses `effective_cpus`/`mem_total_mb` (cgroup-aware, same probes as every tuner) instead of `nproc`/`dmidecode`; `classify_block_device` reads the rotational flag through `${SETUP_SYS_BLOCK:-/sys/block}` like its sibling helper. |
| `tests/stress-site/guest-cache-cookie-test.sh` | XenForo 2.3 renders log out as a POST form; the test sent the pre-2.3 GET and reported two false failures. It now posts `_xfToken` and asserts a token exists (62/62 pass). |
| `lib/services.sh`, `lib/service-optimizers.sh` | XenForo data-cache guidance corrected: with **php-redis** over the Valkey Unix socket the cache measured **+5–7 %** authenticated throughput, not slower (see §5). The old note came from the pure-PHP Credis fallback. |
| `server-configs-nginx` (`h5bp/php_xf.conf`, `h5bp/php_chev_cache.conf`) | `fastcgi_cache_background_update on;` moved into the shipped tree. `--optimize` used to patch it into the live file after every sync, so install left a tree that differed from the optimized one. |

## 5. Tuning sweeps (XenForo 2.3.13)

All runs: 100 s connections, 2 s warm-up, 10 s measurement, Anubis on unless
stated. `member` = `GET /` with a member session, `thread` = seeded thread,
`bypass` = guest with `xf_session=bench-bypass`.

### OPcache JIT

| JIT | member | thread | bypass |
|---|---:|---:|---:|
| off | 514 | 541 | 577 |
| function | 505 | 535 | 559 |
| **tracing 64 MB (default)** | **548** | **569** | **610** |
| tracing 128 MB | 557 | 571 | 612 |
| tracing, hot 128/128/32/64 | 555 | 570 | 619 |
| tracing, hot 32/64/8/32 | 551 | 569 | 614 |
| tracing, 8k root / 256 side traces | 543 | 566 | 603 |

Tracing is worth **+6–7 %** over no JIT; the shipped 64 MB buffer and default
thresholds are at the optimum (larger tables are neutral-to-worse).

### PHP-FPM worker count (`pm=static`)

| children | member | thread | bypass |
|---|---:|---:|---:|
| **16 (1.0/CPU, default)** | **548** | **569** | **610** |
| 24 | 536 | 537 | 599 |
| 32 | 534 | 538 | 590 |

The host is CPU-saturated at 16 workers (88 % user + 6.5 % sys across all
threads); more workers only add context switching. `validate_timestamps=0`
measured within noise (557/570/619), so the safer default stays.

### XenForo data cache (Valkey, Unix socket, phpredis)

| Cache | member | thread | bypass |
|---|---:|---:|---:|
| **enabled (default deploy)** | **563** | **571** | **620** |
| disabled | 516 | 531 | 616 |

With phpredis the local Valkey cache is a **+7–9 %** win for authenticated
traffic; the earlier "slower" note applies to the bundled pure-PHP Credis
fallback used when php-redis is absent.

### Anubis

| Variant | guest cached | static (59 KB CSS) | member | thread |
|---|---:|---:|---:|---:|
| disabled | 83,686–90,152 | — | 563–577 | 571–589 |
| enabled, GOMAXPROCS=8 (default) | 31,302–32,085 | 8,667 | 553–557 | 570 |
| enabled, GOMAXPROCS=16 | 31,180 | — | — | — |
| enabled, static bypass off | — | 7,829 | — | — |

Anubis costs **~64 % of the cached-guest ceiling** and **2–5 %** of dynamic
throughput on this host (the published audit measured −90 % / −18 % before
the Unix-socket back end, gzip-stored cache bodies and `aio off/brotli off`
cache hits). GOMAXPROCS=8 remains the right compromise; the static-asset
shadow bypass is worth **+10.7 %** on real assets. Anubis disable/re-enable
is atomic: 0 failed requests, vhosts restored to direct TLS and back.

## 6. Benchmarks vs the published reference

Host B of the public benchmark is the same machine class (Ryzen 7 8745HS,
16T, 27 GiB, NVMe). PHP 8.5, 16 workers, guest cache warm.

| Tier | Reference (Stack 3) | This host, Stack 3 | Reference (Stack 4, Anubis) | This host, Stack 4 (final) |
|---|---:|---:|---:|---:|
| Guest cached | 56,574 | **90,152** (+59 %) | 5,792 | **31,302** (5.4×) |
| Guest bypass | 656 | 652 | 519 | **607** (+17 %) |
| Member home | 537 | **574** (+7 %) | 438 | **557** (+27 %) |
| Member thread | 431 | **550** (+28 %) | 383 | **570** (+49 %) |
| WordPress guest | — | 15,563 → 90,818 (optimized) | — | 29,393 |
| Chevereto `/` (bypass by design) | — | 2,508 | — | 2,280 |
| Static (small file) | — | 424,090 | — | 50,442 |

Other observations:

* A handful of `X-Forwarded-*`-style header/cookie tests and 54/54 security
  probes pass unchanged; the 62/62 guest-cache cookie suite passes after the
  XenForo logout fix.
* The `E_ALL` experiment above is the largest single regression found:
  529/540/566 → 577/589/643 (**+9 %**) by restoring the shipped
  `E_ALL & ~E_DEPRECATED`.
* Static assets through Anubis are ~50k req/s for a small file; a 59 KB CSS
  file is TLS/bandwidth-bound at 8.7k (bypass) vs 7.8k (through Go).
* Guest cache bodies are served with `Content-Encoding: gzip` and
  `X-Cache-Status: HIT`, `aio off`, `brotli off`.
