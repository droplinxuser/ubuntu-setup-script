# Audit — 1.22.2 (XenForo on PHP 8.1-8.6, TLS libraries, kTLS)

Date: 2026-11-26
Host: the Xeon E-2236 test host (6C/12T, 62 GB, md RAID0 NVMe, Ubuntu
26.04.1, kernel 7.0), reinstalled before the cycle; mitigations off (the
host's standing benchmark state), clock pinned at 3.6 GHz for every
measurement.  Pair: `server-configs-nginx` 1.7.3 (branch `main`).

## 1. Scope

1. Primary focus:
   (a) XenForo on every source-built PHP series 8.1-8.6, plain stack
       (nginx + PHP-FPM + MariaDB; no Valkey, no Elasticsearch);
   (b) nginx with alternative TLS libraries;
   (c) kTLS.
2. Full code audit of both repositories (37 findings), with the
   highest-impact ones fixed in this release.
3. Repositories reduced to one branch each (done before the cycle's
   release: server-configs-nginx `main`, tags `nginx` and `angie-final`;
   this repository's `v1.22` became tag `v1.22.0-history`).

## 2. Method

* Pristine baseline manifest recorded (695 packages), then a fresh install:
  `--basic mitigations=off --nginx --php ver=8.5 --mariadb --valkey
  --elastic --others all` with WordPress, XenForo and Chevereto
  (`wp.test.local`, `xf.test.local`, `chev.test.local`).
* Install: 12 min 37 s, 0 WARN/FAIL lines in 1,557 log lines; after the
  reboot every service active and no journal errors.  Two `--optimize`
  runs (137 s, 138 s); the second reloaded and restarted nothing.
* Apps deployed and exercised: 0 unexpected responses, security 76/76,
  cookie 109/109 after the fixes.  Raw rows of sections 4-6 are in
  `raw-20261126-1.22.2/`.  Compatibility: only XenForo-core
  `E_DEPRECATED` on PHP 8.5 (upstream).
* Benchmarks: 5 rounds, arm order reversed every other round, cold arm
  switch, every row gated (HTTP status, page marker, cache status), median
  and min-max spread.  A change under ~3 % inside the spread is noise.

## 3. Findings fixed

### 3.1 Security: XenForo guest-cache poisoning with zero-padded cookies (high)
`xf_language_id=0000002` is seven characters, so it missed the `{1,6}`
key class and was keyed as the default guest page, while XenForo int-cast
it to 2 and rendered language 2.  Reproduced: with the 1.7.1 maps, a
cookieless guest after three zero-padded requests got a HIT on the
language-2 page.  server-configs-nginx 1.7.3 strips leading zeros in the
key maps and bypasses values with more than six significant digits;
`--optimize` writes the same guards into the legacy `$setup_xf_guest_bypass`
map, which also lacked the `[^0-9;]` guard (`%32`, `+2`, `2x`).  New cases
in `guest-cache-cookie-test.sh` and `tests/test-tuning.sh`; after the fix
the same sequence gets MISS.

### 3.2 Security: CDN proxy cache key (medium)
`proxy_pass $cdn_origin` forwards the raw request line, but the key used the
decoded `$uri`: `/proxy.php%3Fimage=x` (an origin 403/404) shared the key
of `/proxy.php?image=x` and blanked it for the error TTL.  The key is now
`$request_uri`.

### 3.3 `--php` alone left OPcache without huge pages (medium)
The memory plan booked huge pages, but only `--basic` wrote
`vm.nr_hugepages`.  `install_php` now syncs the managed sysctl line first
(`sysctl_hugepages_sync`; untouched for unmanaged files and containers).

### 3.4 `--upgrade-php` tuned from different inputs than `--optimize` (medium)
It now ignores `SETUP_*` tuning env and resets operator pins like
`run_optimize`, so the pool it builds is the one `--optimize` keeps.

### 3.5 Harness repaired for the PHP-series benchmark
The PHP matrix scripts still assumed Sury packages, per-version sockets
and Valkey.  New: `install-php-series.sh`, `switch-php-arm.sh series-X.Y`,
`bench-xf-php-series.sh` + `xf-series.tiers`, `PLAIN=1` deploys, member
cookie and median thread written by `seed-xf.sh`, independent p99 medians,
CPU ms/req and MHz in every row.

### 3.6 Opt-in TLS-library and kTLS builds
`tools/nginx-build.sh build-arm DIR` builds a benchmark nginx into its own
prefix, never activated, with `TLS_LIB=openssl|aws-lc|boringssl`,
`KTLS=0|1` and `OPENSSL_VERSION=lts` (newest 3.5.x).  The TLS choice is
hashed into `build.info` (`tls_opts=`), so `check` reports a changed
library as stale.  The fleet default is unchanged (OpenSSL, no kTLS;
build recipe 5).

## 5. TLS libraries

Arms (`build-arm`, nginx 1.31.10, same clang/LTO flags, same PCRE2,
zlib-ng and Brotli as the live build): OpenSSL 3.5.9 (LTS), OpenSSL 4.1.0
(the fleet's library), AWS-LC 5.15.0, BoringSSL 0.20261105.0.  wolfSSL
(no patch past nginx 1.28.1), LibreSSL (low value) and rustls-libssl
(swaps the library under a distro nginx only) were not built.

Harness: `tests/stress-site/tls-arms-bench.sh`, each arm a standalone
nginx on its own ports with one arm-neutral config (TLS 1.3 only, no
session cache or tickets, no stapling, one certificate per server).  nginx
on 8 logical CPUs (8 workers), wrk on the other 4; the client is Ubuntu's
OpenSSL 3.5.5.  Handshake tiers make a full handshake per request
(`Connection: close`); keep-alive tiers reuse connections.  5 rounds,
order reversed every other round, clock pinned at 3.6 GHz, production
sysctl.  0 failed rows.

| tier | OpenSSL 3.5 | OpenSSL 4.1 | AWS-LC | BoringSSL |
|---|---:|---:|---:|---:|
| H-pq (ECDSA, X25519MLKEM768) req/s | 3,615 | 3,973 | 4,007 | 4,003 |
| — nginx CPU ms per handshake | 0.517 | 0.482 | 0.253 | 0.274 |
| H-x25519 (ECDSA, X25519) req/s | 3,966 | 4,413 | 4,462 | 4,458 |
| — nginx CPU ms per handshake | 0.449 | 0.410 | 0.219 | 0.229 |
| H-rsa (RSA-2048, X25519) req/s | 4,305 | 4,803 | 4,939 | 4,945 |
| — nginx CPU ms per handshake | 1.385 | 1.409 | 1.140 | 1.109 |
| K-1k keep-alive req/s | 237,447 | 236,041 | 231,489 | 230,192 |
| K-page (XF guest page, 105 KB) req/s | 37,359 | 37,182 | 37,426 | 37,319 |
| — nginx CPU ms per request | 0.177 | 0.177 | 0.153 | 0.145 |
| B-1m MB/s | 4,055 | 3,963 | 4,117 | 4,147 |
| B-16m MB/s | 3,830 | 3,717 | 3,830 | 3,840 |
| — nginx CPU ms per 16 MB | 19.4 | 19.4 | 17.2 | 15.9 |

Spreads: handshake tiers 0.1-1.8 %, K tiers 0.9-3.7 %, bulk 2.0-8.4 %.

* Handshake req/s is capped by the client (wrk's OpenSSL verifies on 4
  CPUs); nginx's own CPU per handshake is the server-side figure.  There
  AWS-LC and BoringSSL need half of OpenSSL's CPU for an ECDSA handshake
  (with or without ML-KEM) and about 20 % less for RSA-2048.  OpenSSL 4.1
  is 7-9 % cheaper than 3.5 on ECDSA handshakes and lets the same client
  finish 10-12 % more handshakes per second.
* Keep-alive and bulk throughput tie within the spread (the client is the
  limit at ~3.8-4.1 GB/s); AWS-LC/BoringSSL spend 10-18 % less nginx CPU
  per byte (AES-GCM).
* Cost of switching the fleet: AWS-LC has no kTLS, no `ssl_conf_command`
  and no stateful session cache (scn uses `ssl_session_cache shared`);
  BoringSSL also lacks OCSP stapling and allows one certificate per
  server; PHP's ext/openssl supports neither.  On this fleet nginx sits
  behind Cloudflare, which reuses origin connections, so full handshakes
  are rare.

Verdict: OpenSSL 4.1 stays the default (it beats 3.5 and keeps every
feature).  `TLS_LIB=aws-lc|boringssl` stays a benchmark option: the
server-configs-nginx tree was not validated against them, and the gain
only matters for an origin that terminates many fresh handshakes itself.

## 6. kTLS

Arms: OpenSSL 3.5.9 and 4.1.0, each without and with `enable-ktls`
(`KTLS=1`), the kTLS arms with `ssl_conf_command Options KTLS;`, `sendfile
on` and the `tls` module loaded.  Same harness as section 5.  Proof that
kTLS engaged: `/proc/net/tls_stat` TlsTxSw rose by one per connection on
every kTLS row and stayed 0 on the others; `ss -ti` showed
`tcp-ulp-tls ... txconf: sw`.  Software kTLS only (loopback has no NIC
offload).

### 6.1 Bug found first: kTLS sendfile stalls at the script's sysctl
With `net.ipv4.tcp_notsent_lowat = 16384` (`configs/system/sysctl.conf`,
set for HTTP/2 prioritisation), a kTLS `sendfile()` queues one 16 KB TLS
record, the socket stays unwritable (unsent bytes above the mark), and the
next EPOLLOUT comes from a ~200 ms timer: a 1 MB file did not finish in
10 s (strace: `sendfile() = 16384`, `EAGAIN`, `epoll_wait` 207 ms, repeat).
32768 stalls too; 131072 and the kernel default run at full speed.  Same
on OpenSSL 3.5 and 4.1, kernel 7.0.  Non-kTLS arms are unaffected, and
raising the mark to 131072 did not change them (section 5 against the
non-kTLS rows below).  Run B therefore ran every arm at 131072;
`tls-arms-bench.sh` refuses a kTLS arm below it, and `nginx-build.conf`
documents the requirement next to `KTLS`.

A second harness bug: a stalled worker survived its master's KILL and kept
accepting on the `reuseport` sockets of the next arm (the first run A was
discarded).  `stop_arm` now kills the workers too and `start_arm` refuses
busy ports.

| — nginx CPU ms per handshake | 0.448 | 0.479 | 0.410 | 0.440 |
| — p50 ms | 4.07 | 6.09 | 3.56 | 5.54 |
| K-1k req/s | 238,478 | 146,926 | 236,655 | 147,937 |
| — nginx CPU ms per request | 0.0326 | 0.0453 | 0.0329 | 0.0460 |
| K-page req/s | 37,176 | 35,973 | 37,152 | 35,934 |
| — nginx CPU ms per request | 0.175 | 0.134 | 0.173 | 0.135 |
| B-1m MB/s | 4,086 | 3,994 | 4,024 | 3,891 |
| — nginx CPU ms per 1 MB | 1.340 | 0.755 | 1.324 | 0.747 |
| B-16m MB/s | 3,850 | 3,564 | 3,901 | 3,195 |
| — nginx CPU ms per 16 MB | 18.5 | 10.8 | 17.8 | 10.6 |

Spreads: handshakes 0.1-0.6 %, K tiers 0.7-4.5 %, B-1m 2.4-7.7 %, B-16m
5.8-19.7 % (kTLS arms the widest).

* Large static files: nginx CPU per byte -40 to -44 %.  Throughput does
  not rise, because the client is the limit on loopback; the 16 MB kTLS
  rows are lower with a wide spread (not explained; the encryption moves
  into the kernel on nginx's cores, which may pace the client differently).
* A 105 KB page: -23 % CPU per request, -3 % throughput.
* 1 KB keep-alive responses: -38 % throughput, +39 % CPU per request
  (record setup through the kernel costs more than OpenSSL in user space
  for a small body).
* Handshakes: +7 % CPU (the ULP and key `setsockopt` calls per connection), p50 +1.5-2 ms.

Verdict: not enabled.  It helps only large static files served with
sendfile, it costs small responses and handshakes, and it needs
`tcp_notsent_lowat` raised for the whole host.  The fleet's origins sit
behind Cloudflare and serve PHP pages (sendfile off) and cached pages
(mostly small), so the trade is negative there.  `KTLS=1` stays a build
option and the `tls` module is not preloaded.

## 7. Open items

* PHP 8.2-8.6 link OpenSSL 4.1.0, which is outside the range php.net
  supports for ext/openssl (< 4.0); 8.1 links 3.6.5, not the 3.5 LTS.
  Candidate: build PHP against OpenSSL 3.5 LTS.
* The remaining audit findings (low impact, mostly tests and help text)
  are listed in the cycle's working notes; two help-text items were fixed
  here (`app=` placement in a `--domain` group, `--upgrade-php=<active>`).
