## 1. Changes

### 1.1 Anubis edge route

Every request on a protected site went through the Anubis Go proxy, even when
the managed policy decides on the User-Agent alone and needs no cookie:
`allow-good-crawlers` and the default-allow for every non-browser client.
The terminator now uses `proxy_pass http://$anubis_route`. Two maps send those
requests straight to the backend socket.  Browsers (`Mozilla`), an empty
User-Agent, the `deny-ai-crawlers` list and `/.within.website/` still go to
Anubis.  The maps and `botPolicies.yaml` are generated from the same patterns.

### 1.2 `--upgrade-php` / `--purge php` without dpkg warnings

Each upgrade logged two `dpkg: warning: ... not empty so not removed`
lines.  One cause was our own `zz-setup-optimize.ini` / `custom_dan.ini` in
`fpm/conf.d`.  The other was apt removing `phpX.Y-common` before the
extensions that share `mods-available`.  Unowned fragments are now removed
after the backup (restored on failure), and the `-common` packages are
purged last.  8.5 -> 8.4 -> 8.5: 0 warnings (2 + 2 before), functional
exercise clean on both, 0 state differences outside the upgrade records.

### 1.3 Test isolation

The web-root hygiene checks read the machine's real `/etc/angie`, so they
failed once Angie was installed on the machine running the suite.  They now
use an empty directory unless a test passes one.

### 1.4 No server identifiers in either repository

Real server addresses, host names and site domains were replaced in both
repositories and their history with RFC 5737 addresses and `example`
names.  CI runs `tools/check-public-ips.sh` on both trees.
