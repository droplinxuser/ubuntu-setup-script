## 2. Findings

### 2.1 fileinfo cannot go
Chevereto's image library calls `finfo_file()`/`finfo_buffer()` on every
upload, WordPress checks every upload's real type with `finfo_file()`, and
XenForo's attachment validators (laminas, flysystem) use it.  Its 10.4 MB
magic database is read-only data, paged in only when used.

### 2.3 Valkey
* Package 9.0.6 links Ubuntu's jemalloc, OpenSSL and libsystemd.  The build
  (9.2.0) links glibc and libgcc_s only.
* Instructions per pipelined GET/SET (perf, contention-proof): package
  6,152; upstream default build (gcc or clang) 5,770; first prototype
  9,430; `OPT="-O3 -flto"` 5,577; final flags via the environment 5,926.
  Any `CFLAGS=` on make's command line cost ~3,500 instructions per request:
  it overrides the sub-makes' own flags, so jemalloc and Lua built at -O0.
* The shipped build, through `setup.sh --source=valkey`, 5 rotated rounds:

| test | package | build + BOLT |
|---|---:|---:|
| GET, pipelined 16 | 1,067,806 | +3.1 % |
| SET, pipelined 16 | 978,234 | +2.6 % |
| GET / SET / HSET / LPUSH / MSET, single | 126,518-136,221 | 0 to +1.5 % |

* Valkey uses ~0.3 % of a member page's server CPU (loopback tiers).

### 2.5 MariaDB and Elasticsearch
* Server CPU split on member pages (package stack): WordPress home php-fpm
  81.1 / mariadbd 6.8 cores-s, XenForo home 22.9 / 3.7, thread 55.2 / 5.0:
  MariaDB is 8-13 %.  Not compiled.
* Elasticsearch (Java) gains nothing from compiling.  A trimmed 9.5.7
  distribution failed in turn on `x-pack-core` and `x-pack-security` (the
  launcher's security auto-configuration), `apm` ("installation is
  corrupt"), the keystore's `x-pack-encryption` settings and ILM/geoip
  metadata.  Not shipped.  XFES itself needs analysis-common, simple query
  string, multi_match, more_like_this, function_score and `_bulk`.

### 2.6 Security: BOLT removed PT_GNU_STACK
`llvm-bolt -use-gnu-stack` re-purposes the `GNU_STACK` program header as the
new code segment's `LOAD`; without the header Linux makes the stack
executable.  The BOLTed php-fpm and Angie of 1.21.69/1.21.70 ran that way.
Valkey's unit (`MemoryDenyWriteExecute=yes`) refused the binary, which
exposed it.  Without the flag BOLT relocates the program headers and keeps
`GNU_STACK RW`; every BOLT output is now checked, and the PHP (4) and Angie
(3) recipes are bumped so existing builds are rebuilt.

### 2.7 Download mirror
`droplinxuser/setup-build-sources` (public): one release per component,
unmodified archives and a `SHA256SUMS`, refreshed daily by its workflow with
the servers' own download code.  Servers use it last and only with a
matching published SHA-256, their own first-download pin, or the mirror's
`SHA256SUMS` (unit-tested: matching, mismatching, missing, published-wins,
off).

### 2.8 Test hygiene
`php_build_remove_support` removed `/var/cache/setup-php-build` by literal
path, and the unit test that exercises it ran as root on the test host during
the PHP sweep: the cache vanished under a running build.  All three builds'
removal paths are now overridable, the tests use scratch paths, and a check
refuses literal `/var/cache/setup-*` / `/run/setup-*` removals.

* unit 1,721 checks, dry runs 235, all passing;

  built and BOLTed in 25 minutes; running binaries are the builds;
* a test vhost with a multi-line `sub_filter`, `sub_filter_once`,
  `limit_conn` (and its zone) and an `auth_basic` area: 5 lines commented
  out with the marker, the page served, `/private/` 401 without and 200 with

* login limiter: 11 POSTs answered, 429 from the 12th;
* security 78/78, cookie 105/105, functional suite 0 failures;
* a plain `--optimize`: all three builds reported current;
* `--optimize --source=none`: drop-ins, tools and the LLVM source removed;
  the test vhost and http.d file byte-identical to the originals.
