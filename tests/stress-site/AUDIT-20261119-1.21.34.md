# Audit — 1.21.34 (Ubuntu 26.04.1, Angie 1.12.4, PHP 8.4/8.5)

Date: 2026-11-19 (second cycle of the day)
Host: OVH dedicated server, Intel Xeon E-2236 (6C/12T), 62 GB RAM, root on
md RAID0 over two PM983 NVMe, bare metal, Ubuntu 26.04.1.  Pristine
baseline: **705 packages**, UFW inactive, UTC, no `/etc/angie`, `/etc/php`,
`/var/www`.  Pair: `server-configs-nginx` **1.6.47**.

Stack versions installed: Angie 1.12.4, PHP 8.5.12 / 8.4 (Sury), MariaDB
11.8.6, Valkey 9.0.6, Elasticsearch 9.5.6, Node.js 26.13.1, Anubis 1.28.2.
PHP 8.6 is still 8.6.0 RC5 without `php8.6-redis`, `-imagick` and
`-igbinary`, so it is not installable for these applications.

## 1. Code audit

Two independent read-only reviews (Angie security/cache/Anubis, and
install/`--optimize` parity with auto-tuning) reported 15 candidates.  Each
was checked on the host or against the code before anything was changed.

| Severity | Area | Finding | Verdict |
|---|---|---|---|
| high | Anubis | a static-looking miss (`/x.css?rest_route=/wp/v2/users`) re-entered Anubis on the `static-assets` ALLOW and reached PHP: WordPress REST JSON returned to a browser UA with no challenge | confirmed live, fixed |
| high | Anubis | `/socket/` route on every terminator; duplicated `Host` (proxy_ws.conf + own headers) made every WebSocket handshake 400, and the prefix bypassed the filter for non-WebSocket requests | confirmed live (400), fixed |
| medium | Angie (1.6.x) | credential limit keyed `POST:/index.php` for Chevereto/Flarum: 30 login POSTs from one public address, no 429 | confirmed live, fixed |
| medium | Anubis | `REDIRECT_DOMAINS` unset: post-challenge redirect to any domain, warning at every start | confirmed, fixed |
| medium | `--upgrade-php` | www pool listener replaced by the template's (adopted hosts with `/run/php/php8.4-fpm.sock` → 502) | confirmed in code, fixed |
| medium | `--upgrade-php` | optional-package failures lost in `run_service`'s subshell; pending list deleted, "skipped 0" | confirmed in code, fixed |
| medium | MariaDB | `innodb_log_buffer_size` = pool/16 (not dynamic) forced a restart on every 256 MB–1 GB pool resize | confirmed in code, fixed |
| medium | parity | Angie cache disk cap from *free* space, measured before PHP/MariaDB/ES installed | confirmed in code, fixed |
| low | Chevereto | `/app/vendor/composer/installed.json` and vendor files served (upstream `.htaccess` denies all of `app/`) | confirmed live, fixed |
| low | sysctl | IPv4 fragment memory 2 MB on this host, IPv6 256 KB (below the 4 MB kernel default) | confirmed live, fixed |
| low | hardening | `X-Original-URL`/`X-Rewrite-URL` reached PHP for WP/XF/Chevereto | confirmed live, fixed |
| low | WordPress cache | 404s not cached | **rejected**: WordPress sends `no-cache` on 404 and the cache honours it |
| low | memory plan | ES direct memory and huge pages not booked | partly: the plan keeps 20 % of RAM unbooked; left as a follow-up |
| low | Flarum | cached guest page may carry another visitor's CSRF token/locale | not testable here (no Flarum package); open |
| low | cache keys | `utm_*`/`fbclid` split guest cache keys | not changed (performance idea, needs measurement) |

Found on the host (zero-warning policy):

* 95 AppArmor `DENIED` lines per install from needrestart's `who` call
  (Ubuntu 26.04 profile lacks nameservice): managed `local/who` block,
  written before the first apt run.  Verified: an apt transaction afterwards
  logs no new `DENIED`.
* The public-80/443 advisory was a `[WARN]` on every default install; it is
  advice, now a note.
* Anubis 1.28.2 still logs `USE_SIMPLIFIED_EXPLANATION is deprecated` at
  start although the variable is not set anywhere; upstream, left.
* Hampel Seeder 1.0.0b11 refuses to run without
  `$config['hampelSeeder']['enabled']`; `seed-xf.sh` sets and removes it.

not appear in the production pass.  XenForo lint also reports a parse error
in an unused bundled vendor file (`braintree/.../Digest.php`).

Most recent fully compatible versions: **WordPress 8.5**, **XenForo 8.4**
(8.5 is clean in production error mode, but XenForo core itself still
raises 8.5 deprecations and two debug-mode 500s), **Chevereto 8.4**
(8.5 functional; its vendor tree carries the same deprecations on both).

thread (`bench-thread-tiers.sh`); Anubis tier with oha.

| Tier | 1.21.33 (morning) | 1.21.34 |
|---|---:|---:|
| Guest cached | ~104,000 steady | 95,168–103,042 |
| Guest cached + Anubis | 27,753 | 27,707–27,827 |
| Guest bypass | 374 | 335–356 |
| Member home | 317 | 288–289 |
| Member thread | 341–368 | 329–335 |

The member tiers are 5–9 % below the morning run.  An interleaved A/B of
the 1.21.33 code (git HEAD) against 1.21.34 on the same host, same session,
shows no regression from this release:

|---|---:|---:|---:|
| 1.21.33 | 353 / 357 | 293 / 285 | 333 / 318 |
| 1.21.34 | 351 / 356 | 283 / 284 | 316 / 317 |

run order), not configuration.
