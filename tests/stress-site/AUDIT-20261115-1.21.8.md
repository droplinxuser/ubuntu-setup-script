## 6. Security findings

1. **WordPress's scheduler was blocked (fixed in 1.6.29).**  `wp-cron.php`
   was denied to everyone, including the loopback POST `spawn_cron()` makes.
   The managed crontab masked it on setup.sh hosts, but a hand-installed
   site lost scheduled posts, updates and plugin jobs.  The endpoint now
   answers loopback only; the shared PHP handler was extracted so both
   locations stay identical.  Verified 403 from the LAN, 200 from loopback.
2. **The dot-segment guard did not match encoded dots (fixed in 1.6.29).**
   `$request_uri` is raw, so `/a/%2e%2e/index.php` passed while Angie
   normalised `$uri`.  Now 400; added to the probe.
3. **A cache-key flood could evict the XenForo guest cache (fixed in
   1.6.29).**  A random `xf_style_variation` per request stored one full page
   per key.  `fastcgi_cache_min_uses 2` neutralises single-shot keys; the
   rate limiter remains the bound for repeated keys.
4. **The CDN template cached private XenForo pages and did not verify TLS
   (fixed in 1.6.29).**  `/media/<id>/` is a permission-checked HTML route
   that was stored for 182 days with cookies stripped; the origin certificate
   is now verified.  The pattern is narrowed to `/attachments/` and
   `/proxy.php`.
5. **51+3 read-only probes.**  Hidden files, backup/dump copies, PHP in
   writable directories, PATH_INFO, dot segments (both spellings), internal
   XenForo/Chevereto trees, unknown `Host`, URL override headers, PUT/TRACE
   and loopback-only wp-cron all answer the documented code.  No bypass was
   found.

## 7. Residual risks and recommendations

- The XenForo upgrader stays reachable by design; enable the commented
  `auth_basic` block or remove `install/` between upgrades.
- XenForo's guest cache stores 301s for an hour; purge `/home/nginx_cache`
  after changing URL or routing options (the deploy harness does).
- Chevereto on 8.4+ needs the upstream `?ImageManager` one-liner; without it
  the first request after an FPM restart fails once.
- An Apache/mod_php host still loses its PHP handler on `--upgrade-php`
  (the purge removes `libapache2-mod-php*` and nothing reinstalls it).  The
  script targets Angie/PHP-FPM; such a host should be migrated first.
- The cache tiers are client-bound on this workstation's Wi-Fi; use the
  wired 1.21.6 figures as the server ceiling.
