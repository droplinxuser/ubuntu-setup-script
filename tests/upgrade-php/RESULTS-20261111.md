# `--upgrade-php` audit - 2026-11-11

Host: `audit-host` (16 logical CPUs, 27 812 MiB RAM, NVMe, Ubuntu 26.04.1).
Sury repository at the time of the run: PHP 8.6.0~rc5, 8.5.12, 8.4.27.

## Runs

| Run | Command | Result |
|---|---|---|
| 8.4 -> 8.6 (RC) | `setup.sh --upgrade-php=8.6` | PHP 8.6 installed and serving; `redis`, `igbinary`, `apcu` not published for 8.6 -> exit 1 / `ATTENTION` |
| 8.6 -> 8.5 | `setup.sh --upgrade-php=8.5` | exit 0; extensions and custom configuration carried |
| 8.5 -> 8.5 (repair) | `setup.sh --upgrade-php=8.5` | exit 0; extra pool socket created after the migration reload |
| no PHP -> 8.5 | `setup.sh --upgrade-php=8.5` after purging every `php*` package | exit 0; mode `install` |
| first 8.4 -> 8.6 attempt (before the lagging-extension fix) | `setup.sh --upgrade-php=8.6` | install failed on `php8.6-redis`; automatic rollback restored 8.4, including `/etc/php`, pool and custom files |

## Extension preservation

8.4 -> 8.6 carried `bcmath` and `intl`; `apcu`, `igbinary` and `redis` were
reported as unavailable for 8.6.0~rc5 (the release shipped only the 30 in-tree
extensions). 8.6 -> 8.5 then carried `bcmath`, `intl` and `igbinary`, and the
default `redis` package was installed again.

Custom files survived every direction:

- `fpm/conf.d/99-audit.ini` (regular drop-in) plus its `cli/conf.d` symlink:
  `upload_tmp_dir=/tmp/custom-upload` was visible through Angie -> FPM after
  the upgrade.
- `fpm/pool.d/extra.conf` (second static pool): its socket
  `/run/php/php8.5-extra.sock` exists after the migration reload.
- The old tree and exact package versions remain under
  `/var/lib/setup.sh/php-upgrade-<timestamp>/php-config`.

drop-in, the extra pool and the extra extensions' `mods-available` files.
`setup.sh --optimize` immediately afterwards reported "configuration already
optimized" for PHP and changed none of the four files.

## Timezone

The host image kept `America/Los_Angeles` in `/etc/timezone` while
`timedatectl` reported `Asia/Manila`. The first upgrade inherited the stale
zone through `--optimize`. `sync_php_ini_template` now prefers `timedatectl`,
and `--upgrade-php` pins `PHP_INI_TZ` to the old tree's value, so a later
upgrade keeps the site's PHP timezone and a following `--optimize` does not
rewrite it.
