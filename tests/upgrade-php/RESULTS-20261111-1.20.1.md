# `--upgrade-php` audit - 2026-11-11 (1.20.1 code)

Host: `audit-host` (16 logical CPUs, 27 812 MiB RAM, NVMe, Ubuntu 26.04.1).
Sury repository at the time of the run: PHP 8.4.27, 8.5.12, 8.6.0~rc5.

## Runs

| Run | Command | Result |
|---|---|---|
| 8.5 -> 8.4 (downgrade) | `setup.sh --upgrade-php=8.4` | exit 0 in 1m10s; `php8.4-fpm` active, socket live, Angie reloaded, XenForo and WordPress answered 200 |
| 8.4 -> 8.5 (upgrade) | `setup.sh --upgrade-php=8.5` | exit 0 in 59s; `php8.5-fpm` active, socket live, both sites 200 |
| 8.5 -> 8.5 (repair) | `setup.sh --upgrade-php=8.5` | exit 0; managed files byte-identical, no reload needed |
| dry run | `setup.sh --dry-run --upgrade-php=8.6` | exit 0; prints the package/extension mapping (`redis` and `igbinary` flagged as unpublished for 8.6.0~rc5) |

Extensions carried across both directions: `igbinary` (the only extension
outside the default profile on this host). The default set (`fpm cli mysql gd
curl xml zip gmp mbstring redis readline`, OPcache bundled from 8.5) was
installed by the shared `install_php()` package builder.

## Parity with install and `--optimize`

After returning to 8.5, the managed files were compared with the same files
from the pre-downgrade 8.5 tree (`/var/lib/setup.sh/php-upgrade-*/php-config`)
and against the output of a plain `--optimize`:

| File | Result |
|---|---|
| `fpm/pool.d/www.conf` | identical after normalising the version string |
| `fpm/conf.d/zz-setup-optimize.ini` | identical after normalising the version string |
| `fpm/conf.d/custom_dan.ini` | `09a5329e3bc8e0ca2c792e5b5f336521` before and after |
| `systemd/system/phpX.Y-fpm.service.d/limits.conf` | `e93dcf7daf08cffe5a9cf749495b7ae3` before and after |

`setup.sh --optimize` immediately after the upgrade reports "configuration
already optimized" and changes no file. The run log records the shared tuner
output (`max_children=16`, `opcache=tracing/64M`), so the upgrade path has the
same audit trail as a fresh `--php` install.

## Notes

- The target version is validated before anything is purged; an unpublished
  version dies with the list of published `phpX.Y-fpm` candidates.
- Custom `.ini` drop-ins and extra FPM pools are migrated with version paths
  rewritten and validated by `php-fpm -t`; rejected files are moved out of the
  live tree with the reason.
- `/etc/php` and the exact old package versions are kept under
  `/var/lib/setup.sh/php-upgrade-<timestamp>/`.
- Timezone is taken from the live `custom_dan.ini`, so an upgrade neither
  forces the host zone nor rewrites the site's PHP dates.
